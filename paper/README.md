# paper/ · shared write-up for the scientific paper

Besides the demo, the team will submit a scientific paper. This folder collects what every piece produces, as it is produced, so that writing the paper at the end means assembling and editing, not reconstructing. It is also the place to study what each piece did and why.

## Layout

| Path | What goes there |
|---|---|
| `outline.md` | Skeleton of the paper (IMRaD). Each section says which notes feed it. |
| `sections/` | The article itself, one Markdown file per section, with its owner (#127). See `sections/README.md`. |
| `notes/<piece>_<short_name>.md` | One note per piece (E1…E12, base grid, product), kept up to date by its owner or their agent. Start from `notes/_template.md`. |
| `figures/<piece>_figN_<name>.png` | Final figures, generated by code in the piece's folder (never edited by hand). Prefix with the piece code: `e2_`, `e8_`, `grid_`… |
| `references.md` | Sources cited in the notes (data products, papers, software). |

## Rules for every agent

1. **Write in English**, like the rest of the repo.
2. **Update your note at the end of every block**, in the same PR as the code: what you did, the numbers, what failed and what is missing. A note that only says "done" is not useful; write it so a teammate can understand and reproduce the piece without asking.
3. **Every number says where it comes from**: the script and the output file (for example `src/ml/logistic_baseline.py` → `data/e2/logistic_baseline.json`). Numbers are copied from outputs, never retyped from memory.
4. **Figures come from code.** Keep the figure script in your piece's folder (for example `src/ml/paper_figures.py`) and commit the image here. Keep each image under about 1 MB (JPEG for photos, PNG for plots).
5. **Write limitations and negative results.** They go into the Discussion and are as valuable as the positive ones.
6. **Say what other pieces can use** from your results, and mention the owner.
7. **Cite sources** in `references.md` with a short key (for example `[Parker2016]`) and use the key in your note.
8. Data stays out of git (see `data/README.md`); only text and figures live here.
