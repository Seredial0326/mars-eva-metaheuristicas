### 3.5 Station selection (orienteering) and solver benchmark

**Tour (E5).** Given stations with a value, the astronaut should visit the subset that collects the most value within the energy budget, the EVA duration, optional time windows and the walkback rule. Stations are snapped to the graph like the habitat. One Dijkstra per station gives the directed minimum-energy cost between every pair, with the walking time measured along that same leg. The leg cost ratio i→j / j→i has percentiles 5/50/95 of 0.625/1.0/1.599, so the order of a tour matters. Service costs service time × 205 W. Up to 20 nodes the problem is solved exactly by a bitmask dynamic program [@HeldKarp1962], with Pareto labels when time also binds. Larger instances (the manual stations plus E8's sand-rock contacts, 27 nodes) are solved by OR-Tools CP-SAT [@ORTools], counted only when it proves the optimum. After solving, the tour is checked against the walkback rule and re-planned if it fails. Station values come from a rubric reviewed against the literature (ridge 5, hollow 4, contact 4, Curiosity site 3). Its sensitivity is tested with eight rubric scenarios. When no tour exists, the planner says why. It checks each station's round trip on its own (habitat, station, habitat, with its service). Any tour that visits a station must contain at least that trip, so if none fits, no tour exists. This is exact for energy and O2, which follow the least-energy legs, and an estimate for duration, since a faster but costlier path is not searched. The planner names the station closest to fitting, the resources it is short of, and the smallest budget that would let it fit, rounded up so the printed minimum always suffices. A CP-SAT search stopped at its time limit is reported as incomplete, not as proof.

**Benchmark (E6).** The exact solvers are compared with four metaheuristics: iterated local search [@Vansteenwegen2009], simulated annealing [@Kirkpatrick1983], ant colony system [@Dorigo1997] and a genetic algorithm. The instances are 60 random ones (N 10–18, with and without time windows), the 49 classic Tsiligirides instances [@Tsiligirides1984] and the four real E5 instances. Each method runs with one parameter setting; the stochastic ones run with three seeds.
